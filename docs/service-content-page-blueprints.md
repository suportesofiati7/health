## How to use this page plan

This is the implementation-level companion to the broader [service content growth plan](service-content-growth-plan.md). It turns the audit into specific page decisions: preserve/improve, consolidate, or create. The proposed query intents are hypotheses to validate against Search Console, Ads search terms where applicable, Business Profile insights and real consultation questions. No search volume is claimed.

**URL rule:** keep every current public route. New slugs below are proposals, not redirects or permission to duplicate an existing intent. Before creating a proposed URL, search the route map, sitemap and repository one last time. If an existing page already answers the same query adequately, upgrade that page and mark the proposed URL “do not create.”

**Page status:**

- **Improve existing:** keep URL and rewrite/expand the page with a specific outline.
- **Existing resource:** retain URL; improve, differentiate or connect it as described.
- **Proposed new:** create only after evidence, query and professional review gates pass.
- **Shared:** one canonical page supports more than one hub; do not clone it.

## G. Inputs required before content production

The repository and public pages do not expose Search Console queries, actual Ads campaigns, appointment question logs, detailed device inventory, exact handpieces/modes, current products/substances or written treatment protocols. Before factual copy is expanded, gather:

1. Search Console query/page export for the last 12–16 months.
